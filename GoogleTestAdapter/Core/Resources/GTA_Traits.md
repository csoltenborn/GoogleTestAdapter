# Creating a trait macros header for a version of Google Test

This folder contains `GTA_Traits_<version>.h` headers, which provide the `*_TRAITS` test macros (see the README's
[trait macros](../../../README.md#trait_macros) section) for the following versions of Google Test (or Google Mock,
which uses Google Test's test macros and thus needs no extra work). A header is named after the first version it
supports; versions whose test macros do not differ share a header.

| Header | Google Test versions |
|---|---|
| `GTA_Traits_1.7.0.h` | 1.7.0 |
| `GTA_Traits_1.8.0.h` | 1.8.0, 1.8.1 |
| `GTA_Traits_1.10.0.h` | 1.10.0 |
| `GTA_Traits_1.11.0.h` | 1.11.0 |
| `GTA_Traits_1.12.0.h` | 1.12.0, 1.12.1 |
| `GTA_Traits_1.13.0.h` | 1.13.0, 1.14.0 |
| `GTA_Traits_1.15.0.h` | 1.15.0, 1.15.1, 1.15.2, 1.16.0 |
| `GTA_Traits_1.18.0.h` | 1.17.0, 1.18.0 (used by the samples) |

All headers have been verified as described [below](#verifying-a-header). This document describes how to create a
header for another version of Google Test.

## How GTA finds traits

GTA does not run any code to find traits; it reads them from the test executable's PDB:

* For each test, GTA looks for the test's `TestBody` method symbol (e.g. `Suite_Name_Test::TestBody`; see
  `Core/TestCases/MethodSignatureCreator.cs` for the symbol names of all test types). Its location is the test's
  source location.
* A trait *(Name,Value)* is encoded as a member function of the test class named `Name__GTA__Value_GTA_TRAIT`
  (see `TraitSeparator`/`TraitAppendix` in `Core/TestCases/TestCaseResolver.cs`). A trait symbol belongs to every
  test whose `TestBody` symbol starts with the part of the trait symbol before the last `::`, i.e. the trait
  function **must be a member of the same class as `TestBody`**.
* The functions are generated by `GTA_TRAITS_MARKER(name1, value1, ...)`, which declares them
  `__declspec(dllexport) static` so that the linker keeps them although they are never called.
* Members of class templates (typed and type-parameterized tests) are only instantiated if they are used, so the
  macros for these tests additionally call the trait functions from the test class' constructor by means of
  `GTA_TRAITS_CALL(name1, value1, ...)`.

## Structure of the header

1. **Version independent part** (everything up to the comment `/* test macros, following the according macros of
   Google Test <version> */`): `#pragma once`, `#include "gtest\gtest.h"`, `GTA_TRAIT_`, the `_VA_NARGS_*` helpers,
   `VA_NARGS_CALL_OVERLOAD`, `GTA_TRAITS_MARKER2`..`16`, `GTA_TRAITS_MARKER`, `GTA_TRAITS_CALL2`..`16`, and
   `GTA_TRAITS_CALL`. Copy this part unchanged from the existing header.
2. **Version dependent part**: one macro per Google Test test macro, each being a copy of the according Google Test
   macro with the trait arguments added:

| GTA macro | Copy of (Google Test 1.18.0) | Defined in |
|---|---|---|
| `GTEST_TEST_TRAITS_(test_suite_name, test_name, parent_class, parent_id, ...)` | `GTEST_TEST_` | `include/gtest/internal/gtest-internal.h` |
| `TEST_TRAITS(test_suite_name, test_name, ...)` | `GTEST_TEST`/`TEST` | `include/gtest/gtest.h` |
| `TEST_F_TRAITS(test_fixture, test_name, ...)` | `GTEST_TEST_F`/`TEST_F` | `include/gtest/gtest.h` |
| `TEST_P_TRAITS(test_suite_name, test_name, ...)` | `TEST_P` | `include/gtest/gtest-param-test.h` |
| `TYPED_TEST_TRAITS(CaseName, TestName, ...)` | `TYPED_TEST` | `include/gtest/gtest-typed-test.h` |
| `TYPED_TEST_P_TRAITS(SuiteName, TestName, ...)` | `TYPED_TEST_P` | `include/gtest/gtest-typed-test.h` |

## Deriving the macros

For each macro of the table:

1. Copy the macro's definition from the target version's Google Test headers and rename it as shown.
2. Append `, ...` to the parameter list.
3. Within the body of the generated test class, add `GTA_TRAITS_MARKER(__VA_ARGS__) \` (e.g. right after the
   `TestBody` declaration; access specifier does not matter).
4. For `TYPED_TEST_TRAITS` and `TYPED_TEST_P_TRAITS` only: add a public default constructor calling the trait
   functions, e.g. `ClassName() { GTA_TRAITS_CALL(__VA_ARGS__) } \`, where `ClassName` is the class being defined
   (`GTEST_TEST_CLASS_NAME_(CaseName, TestName)` resp. `TestName`).
5. `TEST_TRAITS` and `TEST_F_TRAITS` call `GTEST_TEST_TRAITS_` instead of `GTEST_TEST_`, passing `__VA_ARGS__`
   as the last argument.

Do not change anything else: the class names, the registration code, and the trailing `TestBody` definition (which
makes the user's test body the body of `TestBody`, and thus the test's source location) must stay exactly as in
Google Test. Internal helpers used by the copied macros (e.g. `GTEST_STRINGIFY_`, `GTEST_SUITE_NAMESPACE_`,
`GTEST_TYPED_TEST_SUITE_P_STATE_`, `GTEST_NAME_GENERATOR_`) are available since `gtest.h` is included, so use them
as they are. If a macro of the target version delegates to another internal macro (like `TEST` does), copy the
macro which actually defines the test class.

Name the file `GTA_Traits_<version>.h` (e.g. `GTA_Traits_1.18.0.h`), add a `Content` item to `Core/Core.csproj`, and
update the table above and the README's trait macros section. If the samples are updated to a new version of Google Test, also update the header which
`GoogleTestNuGet/Build.ps1` puts into the Google Test NuGet packages as `GTA_Traits.h`.

## Verifying a header

Compile and run the following `probe.cpp`, which uses each macro once, against the target version
(`GTA_Traits.h` being a copy of the new header; Google Test 1.8.x and earlier need `/std:c++14` and the
`*_TEST_CASE_*` macros instead of `*_TEST_SUITE_*`):

```cpp
#include "GTA_Traits.h"

TEST_TRAITS(Plain, Test, Type, Small, Author, Me) { EXPECT_EQ(1, 1); }

class Fixture : public ::testing::Test {};
TEST_F_TRAITS(Fixture, Test, Type, Medium) { EXPECT_EQ(1, 1); }

class Param : public ::testing::TestWithParam<int> {};
TEST_P_TRAITS(Param, Test, Type, Large) { EXPECT_GT(GetParam(), 0); }
INSTANTIATE_TEST_SUITE_P(Inst, Param, ::testing::Values(1, 2));

template <typename T> class Typed : public ::testing::Test {};
typedef ::testing::Types<int, char> MyTypes;
TYPED_TEST_SUITE(Typed, MyTypes);
TYPED_TEST_TRAITS(Typed, Test, Type, Typed) { EXPECT_EQ(sizeof(TypeParam), sizeof(TypeParam)); }

template <typename T> class TypedP : public ::testing::Test {};
TYPED_TEST_SUITE_P(TypedP);
TYPED_TEST_P_TRAITS(TypedP, Test, Type, TypedP) { EXPECT_EQ(1, 1); }
REGISTER_TYPED_TEST_SUITE_P(TypedP, Test);
INSTANTIATE_TYPED_TEST_SUITE_P(Inst, TypedP, MyTypes);
```

From a VS developer command prompt (e.g. after calling `vcvars64.bat`), with `G` pointing to the `googletest`
folder of the target version (e.g. `ThirdParty\googletest\googletest`):

```bat
cl /nologo /EHsc /std:c++17 /Zi /MDd /W3 /I"%G%\include" /I"%G%" probe.cpp "%G%\src\gtest-all.cc" "%G%\src\gtest_main.cc" /Fe:probe.exe /link /DEBUG
probe.exe
```

The header must compile without errors or warnings, and all 8 tests must pass. Then check that GTA finds the traits
by running the tests with the GTA build of this repository (after building `GoogleTestAdapter.sln`), once per trait:

```bat
vstest.console.exe probe.exe /TestAdapterPath:<repo>\out\binaries\GoogleTestAdapter\Debug\Packaging.GTA /TestCaseFilter:"Type=Small"
```

| Filter | Expected tests |
|---|---|
| `Type=Small` | `Plain.Test` |
| `Author=Me` | `Plain.Test` |
| `Type=Medium` | `Fixture.Test` |
| `Type=Large` | `Inst/Param.Test/0`, `Inst/Param.Test/1` |
| `Type=Typed` | `Typed/0.Test`, `Typed/1.Test` |
| `Type=TypedP` | `Inst/TypedP/0.Test`, `Inst/TypedP/1.Test` |

Make sure that Microsoft's *Test Adapter for Google Test* does not handle the executable instead of GTA (see the
README's troubleshooting section); its output is prefixed with `Test Adapter for Google Test:`.

Finally, if the header is to be used by the samples, include it from `SampleTests/Tests/gtest_wrapper.h` and
`SampleTests/CrashingTests/CrashingTests.cpp`, and run GTA's test suite, which checks the traits of the sample tests
(e.g. `Core.Tests/GoogleTestDiscovererTraitTestsBase.cs`).
